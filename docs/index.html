Analyze and debug T-SQL stored procedures right from your VS Code IDE

A VS Code / Cursor extension that wraps sql-sp-harness to generate safe debug harness scripts — DML replaced with SELECT previews, variables traced with PRINT, no writes to real tables.

What it does ?

Not a live debugger — a thin UI shell around the Python CLI. It generates a static harness script you review, then run on a dev database.

Analyze Procedure

Tabbed panel with Summary counts, Warnings, and Identified line-level detail. Save the report or jump to source lines.

Generate Debug Script

Opens a new SQL tab with the harness script — DML stubbed, variables traced, deploy preamble removed.

Automatic backend setup

Detects Python on activation and runs pip install sql-sp-harness when the package is missing.

Right-click & palette

Commands on any .sql file from Explorer, editor, or tab. Selection support when text is highlighted in the editor.

Not a live debugger. This tool does not attach breakpoints or step through procedures on SQL Server.

How it works ?

The extension spawns python -m sql_sp_harness with your SQL file (or selection) and surfaces results in VS Code panels and output channels.

Installation and Quick Start

Requires VS Code ^1.85, Python 3.10+, and the sql-sp-harness PyPI package (auto-installed by default).

Step 1. Install the extension

VS Code Marketplace (coming soon)

Marketplace listing coming soon. Or open Extensions (Ctrl/Cmd+Shift+X) and search SQL SP Harness.

Step 2. Verify the Python backend

pip install sql-sp-harness
python3 -m sql_sp_harness version

On first activation the extension auto-runs pip install when spDebug.autoInstallBackend is enabled.

Step 3. Open a .sql file and run Analyze or Generate

Right-click .sql → SQL SP Harness ▸ Analyze Procedure
Right-click .sql → SQL SP Harness ▸ Generate Debug Script

Step 1. Clone and build the VSIX

git clone https://github.com/DeeprajDeveloper/vscode-sql-sp-harness.git
cd vscode-sql-sp-harness

Settings

Grouped under SQL SP Harness in VS Code Settings.

SQL SP Harness

Setting Default Description
spDebug.pythonPath empty Python executable (auto-detect if empty)
spDebug.pipPackage sql-sp-harness PyPI package to install
spDebug.autoInstallBackend true Run pip install on activation when missing

SQL SP Harness › Generate

Setting Default Description
spDebug.traceStyle print print or raiserror for variable traces

SQL SP Harness › Logging

Setting Default Description
spDebug.logToOutput true Show step log in Output channel
spDebug.saveLogFile false Save <proc>.log beside source file
spDebug.quietWhenLogging true Pass --quiet on generate
Step logs. With spDebug.logToOutput enabled, the full backend audit log appears under --- Step log --- in the SQL SP Harness output channel. See the backend docs for CLI logging options.
